# Диагноз C3 — «событие перестало переноситься в другой календарь»

> Дата: 2026-09-10 · Среда: **staging** (`https://dev.neuroboost.website`, deploy `9dfb09f` =
> `origin/develop` HEAD, проверено `gh run list`) · Метод: настоящий browser (Playwright),
> захват network-запросов, ноль правок в коде.
>
> Слова Дениса: *«событие перестало переноситься в другой календарь, он в целом дает типо
> перенести и сохранить, но после этого его статус не меняется, он не переносится, тоже самое
> с повторяющимися»* · *«Насчет только это или все он один раз спросил, дальше перестал, и
> никакой желтой строки не было»*.

## Вердикт — одной строкой

🔴 **`handleSave` в `web/src/components/Calendar/EventEditor/useEditorForm.ts` — stale closure:
`calendarId` не входит в deps `useCallback` (строка 291), поэтому при смене ОДНОГО календаря
save видит старое значение, считает `calendarChanged = false`, удаляет `calendarId` из body
(строки 245–251) и шлёт PATCH без `calendar_id`.** Сервер отвечает 200 — ему нечего менять.

Подозреваемые из задания: **№1 (`CalendarPicker` без `<option value=''>`) — опровергнут со
свидетелем**, **№2 («Запомнить выбор») — на staging у Дениса не подтверждён**, но механизм
воспроизведён и объясняет «спросил один раз, дальше перестал». Настоящая причина — **№3**.

## Что наблюдалось — verbatim

Тестовый аккаунт `c3ui-1789055818@example.com` (throwaway, создан через API), два календаря:
`4fab2cce-…` («Мой календарь», personal) и `9977ec74-…` («C3 target»). Событие `C3 plain`
(`e7f30f4f-…`) и серия `C3 recurring` (`c2bbfec3-…`, `FREQ=DAILY;COUNT=10`), оба в personal.

### A. Обычное событие, меняется только календарь — 🔴 дефект воспроизведён (2 раза подряд)

Editor открыт двойным кликом. Picker отрендерен, `#event-calendar` показывает
`Мой календарь` (`value = 4fab2cce-…` = настоящий `calendar_id` события, совпадает).
Выбран `C3 target`. **До нажатия «Сохранить»** проверено: DOM `select.value` = `9977ec74-…`,
и React-prop `value` на том же `<select>` (через `__reactProps$`) = `9977ec74-…`. То есть
`setCalendarId` сработал, state обновился.

Нажато «Сохранить». Запрос (request 25, повтор — request 28, тело идентично):

Последующий `GET /api/events` (request 26) — событие по-прежнему в `4fab2cce-…`.

**`calendar_id` в теле нет. `?scope=` в URL нет (обычное событие — правильно).**

### B. То же событие, календарь **плюс title** — 🟢 переносится

Тот же editor, выбран `C3 target` **и** title изменён на `C3 plain B`. Request 31:

```
PATCH https://dev.neuroboost.website/api/events/e7f30f4f-d3bc-4ac6-b2b7-12a0b875675a
{"title":"C3 plain B","starts_at":"2026-09-10T09:00:00.000Z","ends_at":"2026-09-10T10:00:00.000Z","all_day":false,"timezone":"Europe/Moscow","reminder_offsets":[1440,60],"calendar_id":"9977ec74-857e-497c-9921-8080e492d34b"}

Ответ `200 OK`, `"calendar_id":"9977ec74-…"`. Событие переехало.

**Это и есть свидетель.** Один и тот же picker, один и тот же `onChange`, одна и та же
цепочка до API — разница только в том, тронуто ли поле, входящее в deps `handleSave`.
`title` входит (`useEditorForm.ts:291`), `calendarId` — нет.

### C. Повторяющееся событие, меняется только календарь — 🔴 дефект + «жёлтой строки нет»

Editor на instance `c2bbfec3-…:2026-09-10`. Picker показывает `Мой календарь` (`4fab2cce-…`,
совпадает с реальным). Выбран `C3 target`, «Сохранить».

Диалог **появился** (settings `recurring_scope` отсутствует → default `ask`). Содержимое

- заголовок «Изменить повторяющееся событие», пояснение — есть;
- **жёлтой строки (`text-amber-300`) нет** — `amberLine: []`;
- «Только это событие» — **enabled, autoFocus** (то есть Enter выбрал бы occurrence);
- «Все повторы» — enabled.

Выбрано «Все повторы». Request 34:

```
PATCH https://dev.neuroboost.website/api/events/c2bbfec3-c04b-40d0-911d-952c6edd0450:2026-09-10?scope=series

## Ответы на вопросы задания

| Вопрос | Ответ |
|---|---|
| Несёт ли PATCH `calendar_id`? | 🔴 **Нет**, когда изменён только календарь (A, C, E). 🟢 Да, когда вместе с ним тронуто любое поле из deps `handleSave` (B, D). Теряется **внутри `handleSave`**: `calendarChanged` вычисляется из захваченного старого `calendarId` (`useEditorForm.ts:245`), даёт `false`, и `delete body.calendarId` (`:249–251`) убирает поле. До `api/index.ts:165` оно не доходит. |
| Есть ли в URL `?scope=`? | Обычное событие — нет (правильно). Повторяющееся — `?scope=series` (по выбору в диалоге или по remembered `series`). |
| Что отвечает сервер? | `200 OK` во всех пяти случаях. Без `calendar_id` в теле ему нечего переносить; `updated_at` обновляется, что и выглядит как «сохранил, но не перенёс». |
| Диалог scope и жёлтая строка? | Диалог **появляется** (при `recurring_scope = ask`). **Жёлтой строки нет** и «Только это событие» **enabled + autoFocus** — потому что в диалог уходит тот же stale `calendarChanged = false`. С настоящим `true` (D) строка есть и кнопка disabled. |
| Рендерится ли `CalendarPicker`, совпадает ли показанное с реальным календарём? | 🟢 Да, рендерится (2 writable календаря). Показанное совпадает: `value = 4fab2cce-…` = `calendar_id` события; после переезда серии показывает `9977ec74-…`. Подозреваемый №1 **опровергнут со свидетелем**: `onChange` срабатывает, React-state `9977ec74-…` подтверждён до save. |

## Корневая причина — `file:line`

`web/src/components/Calendar/EventEditor/useEditorForm.ts`:

- `:71` — `const [calendarId, setCalendarId] = useState('')`
- `:214` — `const handleSave = useCallback(async () => { …`
- `:234` — `calendarId: calendarId || undefined` — читает `calendarId` из closure
- `:245` — `const calendarChanged = Boolean(isEditing && draft && (draft.calendarId || '') !== calendarId)` — из closure
- `:249–251` — `if (isEditing && draft && !calendarChanged) delete body.calendarId`
- `:280` — `}, { calendarChanged })` — тот же stale-флаг уходит в `withScope` → `planMutation` (`useRecurringScope.tsx:40`) → `RecurringScopeDialog` (`calendarChanged` → строка `:72–74`, `disabled` `:80`)
- 🔴 `:291` — deps: `[title, validation, tags, reminderOffsets, startDateLocal, endDateLocal, timezone, isAllDay, description, location, color, isEditing, draft, showReflection, reflection, repeatType, repeatEndType, repeatCount, repeatUntil, onPatched, onCreated, withScope]` — **`calendarId` отсутствует**

Механика: при открытии editor init-effect (`:100–186`) ставит `title`, `validation` и т.д. —
это deps, `handleSave` пересоздаётся и захватывает `calendarId = draft.calendarId`. Дальше
пользователь меняет **только** select → `setCalendarId` меняет state, но ни один dep не
изменился → `handleSave` остаётся старым и видит `calendarId === draft.calendarId`.

ESLint это знает: `cd web && pnpm lint` →
`useEditorForm.ts 291:6 warning React Hook useCallback has a missing dependency: 'calendarId'`
(`react-hooks/exhaustive-deps`). Это одно из тех «4 warnings», которые `CLAUDE.md` gotcha 17
называет безобидными; в CI lint не гоняется.

⚠ Почему это не поймали ни тесты, ни прошлые два чтения: код *читается* правильно — каждая
строка делает то, что говорит; неверен только **момент**, в который `calendarId` прочитан.
Такое видно только при исполнении.

## Что НЕ удалось наблюдать

- **Проход самого Дениса.** Его слова совпадают с A/C/E по симптомам (HTTP 200, «не
  переносится», «жёлтой строки не было», «спросил один раз»), но его клики я не видел.
- **Значение `recurring_scope` у Дениса:** на staging (`neuroboost_dev`) — **отсутствует**
  (1 аккаунт, `settings->>'recurring_scope' = NULL` → default `ask`). Значит на staging диалог
  ему должен показываться каждый раз. «Дальше перестал» воспроизводится только через
  «Запомнить выбор» (E) — либо он его ставил и потом снял/сбросил, либо проверял на **prod**,
  куда я по условию не ходил. ⚠ Не проверено.
- **Мобильный viewport** — не проверялся, опыт на desktop.

## Побочное наблюдение (вне задачи, не исправлять здесь)
